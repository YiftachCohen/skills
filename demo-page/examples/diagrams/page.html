What changes? Before and after, in the same layout

Hand-drawn, because position carries the meaning: every node keeps its place, so the eye sees only what moved. The search-rollout sample: search used to cross the network on every keystroke, and now stops in the browser.

For a single system without a before state, see the architecture diagram in the search-rollout example.

In what order do things talk? A sequence diagram

Mermaid, because a sequence is a list of messages and auto layout gets it right. Use it for request paths, handshakes and retries: anything where the order of calls is the point.

What happens next, and where does it branch? A flowchart

Mermaid for branching logic with more than a handful of paths. Mark the path the story is about :::focus. When a flow is the page’s main picture and fits in one row, draw it by hand instead.

What states can it be in? A state diagram

Mermaid. Use it for lifecycles: an order, a job, a deploy, a PR. Name each transition by what causes it.

What does the data look like? An entity diagram

Mermaid. Use it when a change adds or reshapes tables. Show only the entities the change touches, with the fields that matter to it. This one uses the search-rollout sample.

What does it look like while it runs? A stageshow figure

When the point is a sequence of moments on a screen (a check turning red, a review landing, a result printing), animate it with stageshow instead of drawing arrows. The babysit-pr page opens with one. For charts of numbers, follow the dataviz skill with the Journal tokens.
